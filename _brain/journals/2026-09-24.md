# 2026-09-24

## Raw stays raw, and both implants get a README

Two decisions, both Tom's, both in the direction of less machinery:

**ApoWiki wikitext is imported unconverted.** The earlier open question was
whether the historical commits should carry raw wikitext or already-converted
markdown. Raw wins. brainpick excludes `raw/` from search results and applies
no rendering to it, so a converted copy there would buy nothing — it is
formatted text either way. What it *would* cost is the clean separation
between what ApoWiki's contributors wrote and what we made of it, which is the
whole strength of the provenance claim. Conversion happens where it pays off,
in the distillation into `knowledge/`. Reasoning recorded in full in
`raw/index.md` (that folder is excluded from the compiled bundle, so it is
named here rather than linked).

**Both implants carry a README aimed at agents.** It states that this is a
brainpick brain implant and what that buys (knowledge graph, semantic search,
typed memory), and gives an agent that finds no brainpick installed enough to
install it unaided — `uv tool install brainpick`, the `pipx`/`pip`
alternatives, the `~/.local/bin` PATH gotcha, and `uvx` for running it without
installing. The minimum version is stated as a number so a reader can check
against what they already have: **brainpick >= 0.7.0**, because that is where
brain format 3 made `type: convention` an engine-recognised memory type. Below
it the conventions are not broken, they are *invisible* — the silent failure
worth naming. Federation/implants landed earlier (0.5.0) and repo-root
`--root` earlier still (0.4.5), but neither suffices alone. Latest is
recommended, not required.

## Apologetics brain implant founded

Founded by porting the stem implant's contract, adapted for a public GFDL
apologetics repository. Three founding decisions, all Tom's:

1. **Shared common brain (federated)** for the Bayesian appraisal tool — a
   fourth repo holding the tool *and* its governing convention, mounted as
   a second brain by each implant. Keeps the tool and its epistemic rules
   together; avoids three-way drift.
2. **Pseudonymize IP authors.** Some early ApoWiki revisions are bare IP
   addresses. Under GDPR an IP is personal data, which collides with the
   "written to be public / no personal info" rule. Registered usernames stay
   as-is (chosen pseudonyms); bare IPs are committed under
   `ApoWiki-anonymous` with the real IP kept only in a local, gitignored
   provenance sidecar. The `no-ip-in-history` henxel blocks bare IPs as git
   authors mechanically.
3. **Scaffold first**, no article content yet. Port the contract,
   conventions, and skills before any ApoWiki article lands.

Scope definition encoded as a convention: apologetics = articles defending
Christian belief against *non-Christian* views; theology = articles defending
one Christian view against *other Christian* views. Both implants hold the
same NPOV rule: we claim that somebody *said* something (true and provable);
what they said may or may not be true, and we do not take a position.

ApoWiki confirmed live at `https://apowiki.fi/api.php` (MediaWiki 1.43.9):
13 254 edits, 494 articles, 290 users, GFDL-1.3-or-later. The full revision
history API exposes `user`, `timestamp`, `comment`, `content` per rev — so
a faithful git-history transcription is algorithmically clean. That work is
the next goal.

## The import had a silent data-loss bug, and checking found it

The first import produced 807 files for 848 pages. That 41-file gap was not
rounding — it was **one page silently overwriting another**, because the slug
function is lossy: `"Jumala ei ole kiva"` and `Jumala ei ole kiva` reduce to
the same name, as do `A.D. 30`/`AD 30` and `C. S. Lewis`/`C S Lewis`. 38 slugs
collided. Each collision interleaved two unrelated revision histories into one
file and discarded one page's identity.

Checked before assuming the worst: every collision turned out to be an
article-and-its-redirect pair, so **no substantive text was lost**. But the
mechanism was still wrong, and it would have lost real content the moment
ApoWiki grew two genuinely distinct pages with similar titles.

Fixed by disambiguating in sorted order with a `-v2` suffix — sorted so the
mapping never depends on directory iteration order, and `-v2` rather than
`--2` because a double hyphen is not kebab-case and `raw/`'s own naming rule
rightly rejected it. The contract caught that second mistake immediately.

Re-imported from the cache, which is exactly why fetching and importing are
separate tools: 8,226 revisions replayed locally in minutes without touching
ApoWiki's server again.

Now 848 files for 848 pages — 471 substantive articles and 377 redirects,
which matches ApoWiki's own count of 494 articles closely enough to be
believable.

**The lesson worth keeping: a count that is nearly right is a bug report.**
807 looked close enough to 848 to wave through, and it was hiding silent data
loss.
