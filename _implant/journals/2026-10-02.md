## Quotes no longer swallow their links

Working down the bare red links turned up targets like *yliluonnollinen*
followed by "> — yliluonnollisia". These weren't wanted pages but a
converter bug. The quote templates (*Lainaus*, *Sitaatti*) split their body
on every pipe, including the one inside `[[target|label]]`. The label then
became the quote's "attribution", and the link fell apart. Splitting on the
template's own pipes fixes 15 articles. *Aukkojen jumala*, *Usko ja tieto*,
*Teleologinen argumentti* and *Modernin ajattelijan uskontunnustus* get
whole quotes with working links, and Bultmann's quote from Bergmann, whose
`1=` parameter used to drop its text, is there for the first time. Two
glossary terms surfaced as a result and got decisions in the converter's
fallback map. The [convert skill](../skills/convert-apowiki-to-articles.md)
is unchanged: the fix is inside the tool.

One more false red link was a URL: *The Edge of Evolution* writes
`[[http://… Sanford osoittaa]]`, which is a typo for an external link. The
converter now renders that as a link to the URL.

The wiki tables carried a stray `\|` in the header cells of 17 articles
(*kreationismi*, *larry-laudan*, *islam* among them). The cell `!{{hl2}} |
text` loses its template before the table converts, which leaves an empty
attribute prefix, and its pipe was kept as text. The table converter now
drops it.

Reviewing the first batch 1 translation showed "> center" at the top of
quotes. *Sitaatti3*'s alignment argument (`center`, `right`) was read as
quote text, and in *fundamentalismi* it even became the description. 14
articles are fixed.

## The batches move to a private llama-server

The shared Ollama sent the translator no request for over an hour: it holds
one model at a time, and the theology compile's embedding stream kept
bge-m3 loaded. The host had llama.cpp's `llama-server` installed, so it now
serves the same 9B Qwen GGUF to this implant alone. `apowiki_translate.py`
speaks to any OpenAI-compatible endpoint ending in `/v1`, set with
`TRANSLATE_ENDPOINT` ([skill](../skills/translate-an-article.md), step 4).
It generates about 1.5 tokens a second while the miner holds most of the
CPU, but nothing can preempt it. Batches 1 and 2 now run in one two-pass
runner, and its restart steps are in the todo.

## Red links: the English Wikipedia as a second fallback

241 red-link targets had no Finnish Wikipedia page. Many are English-language
scholars and books (*George Gaylord Simpson*, *Douglas Futuyma*, *The Design
Revolution*), so `apowiki_redlinks.py --lang en` looked them up in the
English Wikipedia: 126 hits. The review rejected nine. Seven were bare
years like *1623*, which name a year and not the subject the article meant.
The other two, *Skepsis* and *Schweitzer*, resolved to the wrong thing, and
were fixed in the Finnish map instead: Skepsis ry and Albert Schweitzer. That
leaves 117 targets in `red-link-wikipedia-en.json`. The converter tries the
glossary, then Finnish Wikipedia, then English Wikipedia, and the red-link
comment stays in every case
([convert skill](../skills/convert-apowiki-to-articles.md)).

Also found while checking why batch 1 is slow: the shared Ollama server only
holds one model at a time (`OLLAMA_MAX_LOADED_MODELS=1`). The theology
implant's `brainpick compile --only t2` keeps bge-m3 loaded with a stream of
embedding calls, so the translator's 9B model waits its turn. That's the
parallel theology session's work and isn't ours to stop. The batch will go
faster once it ends.

finished chunks. The shared CPU host was busy with another user's embedding
job, the fifth request passed the one-hour HTTP timeout, and the exception

([skill](../skills/translate-an-article.md)). A second runner,
`_temp/run-batch1b.sh`, waits for the first to finish and retries whatever
batch 1 is still missing.
