# 2026-09-27

## `_brain/` renamed to `_implant/`; vocabulary made consistent

Tom's instruction: this repository is not a brain, it is an **implant**.
brainpick registers exactly one repository per agent as its **cortex** (the
agent's own brain). Every other registered repository, or a subfolder of one,
is an implant. So every `brain-implant-*` repository keeps its data in
`_implant/`. The philosophy and cognitive-tools implants already did. This
one and theology now follow.

What changed:

- The bundle root is renamed, with `git mv` so history follows. Every path
  in the contract, the tools, the README and `brainpick.toml` now says
  `_implant`.
- The prose now says *implant* where it meant this repository. The contract
  rules read "One implant, one bundle root", "the implant's work queue", and
  so on. brainpick's own terms stay as they are: `brain://` links, the
  `brain_*` tools, *brain format 3*, and the `[brain]` table in
  `brainpick.toml`. They name the engine's concepts, not this repository.
- The usage skill is now [Using the brain implant](../skills/using-the-brain-implant.md),
  rewritten on the model the philosophy implant already uses. The cortex
  holds verdicts; this implant holds what was said, by whom and where.
- The local registry mounts this repository at `_implant`, and the cortex
  role is spelled `cortex` (brainpick still reads the legacy `user`).

Archived journals keep their original wording because they are history.
