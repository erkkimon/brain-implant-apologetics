# 2026-09-27

## Translation with small local models, bound to ApoWiki's glossary

Tom asked whether cheaper models could translate, taking ApoWiki's Finnish
vocabulary into account. The answer and the machinery are now in the
implant:

- **ApoWiki's glossary is in.** `ApoWiki:Sanasto` (revision 11402, 413
  terms) is stored unconverted in `raw/apowiki-project/sanasto.wiki` with the
  GFDL notice, and converted to [Sanasto](../knowledge/glossary/sanasto.md)
  with one anchor per term. ApoWiki's struck-through senses are marked as
  usage it avoids. The page lists two terms twice; their definitions are
  merged. A new contract rule puts the GFDL notice requirement on
  `raw/apowiki-project/` too. The tool is `skills/tools/apowiki_glossary.py`.
- **The 401 `AW:S#term` links in the articles now land** on that page
  instead of being dropped to plain text. 48 of them point at 41 terms the
  glossary never defined; those land on the page itself (queued in
  todo/open.md).
- **The converter now honours MediaWiki's link trail.** `[[aihetodiste]]et`
  now renders as one linked word, *aihetodisteet*, instead of a link followed by a stray "et".
  Finnish inflects by suffix, so this changed links in 227 files.
- **The converter now reads numbered lists written without a space**
  (`#Jos Jumala on…`), and nested ones (`#*`). Markdown rendered those as
  broken headings: 4 467 lines in 451 articles, including the premises of
  the problem-of-evil argument.
- **Model trial.** On the ollama host only the Qwen 3.5 models up to 9B
  actually load. The 14B–32B models are listed, but their weight files are
  missing, and there is no GPU driver, so everything runs on CPU. A 4B and
  a 9B translated the same two paragraphs: both fluent and faithful on the
  argument, but both dropped a link and invented an English title for a
  Finnish book. A full 9B run over *Pahan ongelma* took 20 minutes: 4 of 5
  chunks passed every check, and one kept its Finnish original after three
  retries.
- **Decision:** the local model writes, deterministic checks decide, and
  frontier tokens only review. The procedure is
  [Translate an article](../skills/translate-an-article.md), the vocabulary
  contract is [English renderings](../knowledge/glossary/english.md) (55
  terms seeded, the most-linked ones), and the plan records the choice and
  a resume section: [the plan](../plans/mvp-then-iteration.md).

## The corpus hangs off the book spine

1 297 of ApoWiki's 1 300 inline scripture references (`{{rp|Matt. 5:32}}`)
now link to their book page. The abbreviation table is in
`skills/tools/apowiki_books.py`. Each [book page](../knowledge/books/index.md)
lists the articles that cite it, most-cited first: 115 articles across 59
books. Only 10 of the 62 book reviews (`Luokka:Kirjat`) cite scripture. The
rest review modern books (Dawkins, Behe, Meyer) and stay under their topic.

## The live annotation check is blocked by vector compilation, not by the registry

`brain_read` in a federated set computes annotations by loading every
other brain's state, and loading a brain whose vectors are stale re-embeds
it on the spot. With only theology and apologetics in the set, the read
still hung in `compile/t2 → embed` (stack dump), because the book pages had
just changed and the embedding host is CPU-only. So the earlier hang was
the same thing. The check has to run right after a completed
`--only t2` compile of both implants.


## `_brain/` renamed to `_implant/`; vocabulary made consistent

Tom's instruction: this repository is not a brain, it is an **implant**.
brainpick registers exactly one repository per agent as its **cortex** (the
agent's own brain). Every other registered repository, or a subfolder of one,
is an implant. So every `brain-implant-*` repository keeps its data in
`_implant/`. The philosophy and cognitive-tools implants already did. This
one and theology now follow.

What changed:

- The bundle root is renamed, with `git mv` so history follows. Every path
  in the contract, the tools, the README and `brainpick.toml` now says
  `_implant`.
- The prose now says *implant* where it meant this repository. The contract
  rules read "One implant, one bundle root", "the implant's work queue", and
  so on. brainpick's own terms stay as they are: `brain://` links, the
  `brain_*` tools, *brain format 3*, and the `[brain]` table in
  `brainpick.toml`. They name the engine's concepts, not this repository.
- The usage skill is now [Using the brain implant](../skills/using-the-brain-implant.md),
  rewritten on the model the philosophy implant already uses. The cortex
  holds verdicts; this implant holds what was said, by whom and where.
- The local registry mounts this repository at `_implant`, and the cortex
  role is spelled `cortex` (brainpick still reads the legacy `user`).

Archived journals keep their original wording because they are history.
