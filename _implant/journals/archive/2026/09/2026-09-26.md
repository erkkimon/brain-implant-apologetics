# 2026-09-26

## Cross-lingual search works: English questions find Finnish articles

The `bge-m3` vector build finished in 81 minutes on the CPU-only backend, far
under the six-hour estimate made from one timed batch. Search now runs in
`keyword, semantic` mode. Four English questions each found the right Finnish
article in the top hits, matched semantically rather than by shared words:

- *Is human reason reliable if naturalism is true?* found Plantinga's
  evolutionary argument against naturalism.
- *Irreducible complexity bacterial flagellum* found *Palautumaton
  monimutkaisuus* and *Darwin's Black Box*.
- *Did Jesus rise from the dead?* found *Jeesuksen ylösnousemus*.
- *Problem of evil and suffering* found *Pahan ongelma* and *Kärsimyksen
  tarkoitus*.

This is the premise of [the plan](../../../../plans/mvp-then-iteration.md) holding:
the Finnish corpus is usable before any translation. One weakness shows. The
keyword half still matches English stop words ("is", "of", "from") against
Finnish bodies that quote English titles, which puts a few irrelevant people
pages among the hits. The semantic hits rank above them, so this can wait
until the gate.


## Bundle ids re-minted; the binding runs both ways

Both implants had 22-character bundle ids. brainpick mints 21
(`generate_bundle_id`), and its `brain://` matcher captures exactly
`[a-z0-9]{21}`, so a 22-character id loses its first character and no link
could ever resolve to it. The ids were re-minted: this brain is now
`3hm51e1pxik7zz5la3bve`, theology `kay4zyljsuy909krumpau`. The theology book
pages now link to their rungs here, and a script confirmed that all 136
cross-brain links land. The theology journal for today records its side.
Nothing outside the two repos had used the old ids.


## The book spine, mirrored as rungs

Phase 2 of [the plan](../../../../plans/mvp-then-iteration.md) began with
`skills/tools/apowiki_books.py`, described in
[the convert skill](../../../../skills/convert-apowiki-to-articles.md). It writes 66
Finnish book pages and two testament pages in
[knowledge/books/](../../../../knowledge/books/index.md). Each page points at the
theology implant's own page for that book, because theology owns the spine
and this brain only mirrors the rungs. The converter uses the tool's alias
table, so 22 wiki links that named a book with no ApoWiki article (for
example `[[Matteuksen evankeliumi]]`) now land on its rung instead of staying
red. Red links: 740 → 718.

**Decision: cross-brain pointers are autolinks.** `<brain://theology-…/path>`
is the form to use, not a markdown link with a `brain://` target. I checked the code rather than the
docs: henxels' `links_resolve` treats any target without `http(s)://` as a
local file and would report a markdown `brain://` link as dead. brainpick
0.8.6's annotation scanner matches the bare URI anywhere in the text. The
autolink therefore passes the contract and still produces the annotation.

A converter bug the spine surfaced: `{{k-he|ספר דניאל}}` was in the
layout-drop list before the language-term rule could run, so every Hebrew
original name vanished and left `()` behind. It is fixed.

The multilingual vector build (`bge-m3`, all 540 docs) runs on a CPU-only
shared backend and takes well over half an hour, so a compile in a foreground
tool call with a timeout gets killed. Run it as a background job.
